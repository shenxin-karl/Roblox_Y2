# 游戏配置

本技能描述跨游戏复用的配置分类与导出协议。具体游戏有哪些子表、字段和业务处理器，以当前工程工作簿与消费代码为准。

先按任务选择子文档，**不要默认同时加载两份**：

| 当前任务 | 按需读取 |
| --- | --- |
| 调用配置 MCP；操作 XLSX；查询 Meta、字段类型、Excel 布局及 Lua/Luau 导出结构 | [MCP 与配置格式](references/mcp-and-format.md) |
| 判断数据归哪个配置文件；组织商品、商店、道具、游戏、活动配置；选择通用字段或独立子表 | [配置分类与组织](references/game-configs.md) |

任务同时涉及业务与编辑时，先明确分类，再加载 MCP 文档操作。

- 通过当前工程的 `sgtk.config.*` MCP 获取配置文件与实际声明，不依赖固定项目路径或预设的子表清单。
- 配置导出目录（含自定义目录）中由源配置生成的 Lua/Luau 文件仅可只读查看，禁止直接编辑、覆盖或临时修补。配置变更必须通过 `sgtk.config.*` MCP 修改原始 XLSX，检查并通过 close 保存成功后，再以返回的 savedRevision 调用 export 更新对应生成文件；不直接覆写 XLSX。
- 能安全读取的文件允许先打开修复；配置错误或保存限制不等于不能打开。检查或保存失败时保留草稿，能通过现有 API 修复则继续修改并重检；MCP 不可用或确实无法修复时报告具体阻断，不手改 XLSX 或生成文件绕过流程。
- 重开会自动刷新无未保存修改的旧会话；脏草稿默认保留。确定放弃旧修改、以磁盘文件为准时使用 open 的 `discardDraft:true`，读取返回的新 contextId 和版本，无需为清草稿重启服务；不能仅因发生冲突就丢弃仍需保留的修改。
- 超链接用 Cell 的 `getHyperlink`、`setHyperlink({sheet,cell})`、`clearHyperlink` 读取、修复或移除；新目标只允许当前工作簿已有页签和单格 A1 地址，不传 URL 或其他文件路径。原有失效导航链接本身不是导表错误，不无差别删除链接。
- 配置脚本查询用 `print(...args)` 输出文本或 JSON 到 `logs`，不从 `result` 取数据；读取实际 `draftRevision` 供下一次调用使用。日志和执行成功不代表检查、保存或导出成功。
- 修改前读取目标 Meta、字段、主键和记录。参考文档中的名称和数值用于解释协议，不保证每个游戏都存在，也不自动要求新增。
- 分类决定数据职责；Meta 决定导出结构；消费代码决定业务字段含义。新增业务字段或处理器时，核对游戏侧接入。
- 只读说明无需保存或导出。修改后区分草稿、已保存、已导出和游戏验证状态；遇占用、版本冲突或不支持格式时报告实际阻断。
