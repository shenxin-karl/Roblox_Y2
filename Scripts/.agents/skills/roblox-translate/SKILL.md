# Roblox 全表翻译与审查

覆盖 `translation-upload.csv` 全部条目、全部已有目标语言，包括非空旧译文。先核实用途，再翻译和复审；脚本只校验结构与记录，不能替代语义判断。

## 输入和边界

- 读取工作区 AGENTS.md 和 [本地化](../roblox-localization/SKILL.md)。本任务可按用户授权维护译文，普通编码任务仍不改翻译产物。
- 输入须为同次导出的 `translation-upload.csv` 和 `translation-ai-context.json`。本工程正式目录为 Git 根的 `GameKitWorkspace/Translation/`，不混用旧 `Scripts/outputs/translations/` 的文件；其他工程先定位实际导出目录。缺文件则记录阻断，不重新导出覆盖审查输入。
- 只改已有语言列的单元格。表头、行数、顺序及 Key、Source、Context、Example、Game Locations、`… translator type` 等非译文列不变；索引只读，不新增语言、排序、去重或上传云端。源文案有问题时报告，不修改代码、配置、UI 节点或 Generated。
- 显式调用 `$roblox-translate` 授权为文案核验进行必要的 Studio 测试或试玩，仍遵守项目与会话边界；自动选中本 skill 或维护 skill 本身不构成试玩授权。静态证据足够时不试玩。

## 工作流程

按 [脚本与审查记录](references/workflow.md) 使用 `scripts/translation_review.py`（仅依赖 Python 3 标准库）。

1. **建档**：先定位已有审查记录；输入匹配时直接续用，无记录才 `init` 保存基线。新导出与旧记录不匹配时按参考文件处理，不覆盖旧基线。`report` 查看行数、语言、缺译、身份/索引问题和旧译文模板错误。
2. **调查**：`batch` 读取未完成条目，按下节核实全部来源，记录当前原文、用途、参数和显示条件。身份匹配与索引新鲜度要求见参考文件。
3. **翻译与复审**：逐语言补译、修正或保留，再按语言和功能通读关联文案；完成后才设 `reviewed: true`。在 `glossary` 维护各概念、各语言的术语与依据。
4. **处理疑点**：保留基线单元格原值，写具体 `pending`，包含疑点、证据、阻断原因和所缺信息。身份歧义不应用修改；多来源用途冲突则整条待确认，不取首项或拆 Key。运行时疑点按参考文件区分整条与单语言范围。
5. **保存与续接**：`report` 查漏，`apply` 校验后保存，再 `report` 核对落盘值。持续更新同一记录，直到全表完成或剩余项均有具体阻断；局部失败不阻断独立条目，上下文不足时依记录续接，不缩减为抽样。

## 产物控制

- **一份当前记录**：正式 CSV 之外，基线、来源结论、术语、语言复审与待确认项集中在一份可独立续审的记录中，避免按批次或日期累积快照、决策表和重复报告。必要截图等证据可另外保留并说明依赖。
- **过程数据临时存放**：MCP 原始响应在会话中处理，只提取所需事实写入 `evidence`；确需保存完整响应、一次性脚本或中间报告时使用系统临时目录，结束后清理本次创建的文件。
- **承接后再清理**：删除旧文件前确认未解决疑点和有效证据已承接，检查依赖并重跑 `report`；按[产物与清理](references/workflow.md#产物与清理)执行。交付时将译文单元格、CSV 记录数和辅助文件变更分开说明。

## 来源调查

| 来源 | 必查内容 |
| --- | --- |
| 代码 | 定义、实际调用、参数来源和显示条件；明确功能、界面/状态及按钮/标题/提示等角色，确认参数是否已带币种、正负号、单位或数字格式。限定路径用 `rg` 追踪，不能只看定义行或变量名。 |
| UI 节点 | 读 [Studio 操作](../roblox-studio-operations/SKILL.md)，用 Roblox MCP 查询 Edit 模板、周围文案、布局及 Text/PlaceholderText、RichText、TextWrapped、尺寸等属性。可按界面合并查询，每条保留结论；本地代码不证明节点存在或同步。 |
| 配置 | 读 [外部工具协作](../roblox-external-tools/SKILL.md) 和 [XLSX 游戏配置](../roblox-external-tools/references/game-config.md)，用配置 MCP 核查工作表、字段、记录并追踪消费代码；生成 Lua、ID 或字段名不能代替用途证据。 |

仅当静态调查无法解决具体用途、参数或显示疑点时，才按 [必要试玩与显示证据](references/workflow.md#必要试玩与显示证据) 核验。

## 翻译与模板

- **语义与表达**：依据当前 Source 和场景，准确表达动作、对象、条件、数量和奖励，使用自然语法与标点；按钮简洁，状态区分清楚，数量明确指向次数、天数、物品或奖励。
- **动态参数**：按实际取值范围代入代表值，检查助词、词尾、单复数、性别、冠词和量词；必要时采用不依赖这些变化的自然句式，不改参数契约。
- **集中复审**：每个语言按功能连读按钮、状态、提示和引导，覆盖旧译文及跨批关联。发现术语漂移时检索整表同概念用法；地区语言分别判断，不机械复制，也不强行统一不同概念。
- **长度与换行**：依据 UI 空间调整，不删含义；使用真实换行而非字面 `\n`，调整后复核布局。具体裁切或遮挡疑点无法静态确认时再试玩。
- **模板**：参数名、大小写、格式和次数完整保留，可调整位置；`{level:int}` 不能改为 `{level}`。纯参数 Source 原样保留，不附加符号、单位或重复格式化。保留富文本标签、属性值、配对与嵌套，移动后检查包裹对象；支持语法见参考文件。

## 交付

依据最终全表 `report` 汇报：

- **覆盖与结果**：条目数、目标语言、来源已查/总数、语义审查已完成/应完成数；相对最初基线的补译、修正、保留、待确认、未审查数，每单元格计一次。
- **校验与复审**：CSV 结构及非译文列检查；占位符、富文本、缺译问题的数量与清单（含未改旧译文）；身份与来源问题；各语言集中复审范围及跨批术语结论。来源核实、语言复审与模板校验分别报告，不互相替代。
- **阻断与试玩**：待确认项的身份、疑点、证据和所缺信息；实际试玩的界面/状态、操作、语言、条目、译文版本、观察及未验证范围，按参考文件区分显示证据。
- **文件状态**：CSV 和审查记录绝对路径，明确云端未上传；失败时按实际结果说明是否保存、哪些修改未应用。

只有全部语言语义复审、全部来源核查及必要验证通过，无缺译、待确认、未处理或校验错误，且结果已落盘，才报告全部完成。
