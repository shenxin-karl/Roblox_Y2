待补充玩家操作、状态变化和反馈闭环。

## 3. 系统规则

- State 记录当前金钱和各槽位是否解锁，初始金钱来自 Config 最外层，初始解锁数量来自“槽位配置”；默认前 5 个槽位（ID 1～5）已解锁，其余未解锁，初始解锁不扣钱。
- 选中槽位后在 Inspector 点击“解锁”，按当前曲线价格扣除金钱并解锁该槽位，不要求先解锁相邻槽位。
- 金钱不足、槽位不存在或已经解锁时不扣钱、不改变解锁状态；同一槽位不能重复购买。

## 4. 交互流程

Game 直接展示 30 个浅蓝色方形槽位按钮，每行 6 个、共 5 行，不使用滚动容器、顶部标题或槽位区外框底色。按钮横纵间距统一为 12px，左上角以小字号显示槽位 ID，中央以灰色显示“未解锁”，解锁后改为“已解锁”。点击槽位后，Inspector 显示槽位详情、当前金钱及“解锁”按钮；未解锁时显示价格，余额不足时禁用按钮，已解锁时按钮显示“已解锁”并禁用。未选择槽位时提示选择槽位。

## 5. 验收规则

待补充可复现的场景、预期状态变化和边界条件。

## 6. 实现说明

金钱保存在 `State.money`，槽位列表保存在 `State.slots`，每项记录 `id` 和 `unlocked`，随状态快照保存与恢复。Game 的槽位按钮只切换编辑器选择，Inspector 的解锁按钮消费 `UnlockSlotAction` 完成扣款与解锁；价格由共用公式按当前 Config 采样，操作支持 Action 序列化回放。
