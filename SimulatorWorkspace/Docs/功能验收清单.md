### 解锁价格曲线

- [ ] **验收完成**

---

> 解锁价格 = 向下取整（价格基础值 + 槽位 ID ^ 价格幂值 × 价格倍率）

- 直接使用目标槽位的实际 ID，无索引偏移。只为存在且未解锁的目标计算价格。
- Inspector 的价格显示、余额校验与实际扣款共用完整曲线，按执行时当前配置计算，不将价格存入 State。
- 输入限制为曲线配置的整数闭区间；不对非法 ID 自动补值或夹取。已解锁槽位不再采样价格。

**配置来源**

### 金钱与解锁结算

- [ ] **验收完成**

---

> 解锁后金钱 = 解锁前金钱 − 当前目标槽位解锁价格

- 新 State 的金钱使用代码固定的零余额，当前不存在初始金钱配置。初始槽位按列表前序免费解锁，其余未解锁；初始解锁不采样价格、不扣款。
- Inspector 的“解锁”按钮，或选中锁定槽位后的 W 快捷键，创建解锁 Action。目标必须存在、未解锁，且余额至少等于当前价格；不要求先解锁相邻槽位。
- 成功只扣价格并将目标设为已解锁，不同时打造武器；余额恰好足够可以成功。余额不足、重复解锁或无效目标时不扣款、不改变状态，不记录成功操作。
- 按钮禁用态复用 Action 条件；成功后刷新余额、Game 槽位文字及 Inspector 状态。改变初始解锁配置不直接重置当前状态。

**配置来源**

初始免费解锁：`config: 初始解锁槽位数`；新 State 按槽位数组索引小于该数量初始化。<br>
购买扣款：`config: 槽位解锁曲线`；按实际槽位 ID 采样，见[解锁价格曲线](#解锁价格曲线)。<br>
初始零余额：代码固定值，来自 `State.money` 初始化及缺省恢复分支。

实现来源：[Main.ts](../Code/Main.ts) 的 State 构造；[State.ts](../Code/State.ts) 的构造函数；[Actions.ts](../Code/Actions.ts) 的 `UnlockSlotAction`；[Game.ts](../Code/Game.ts) 的 `upgradeSlot()`；[Inspector.ts](../Code/Inspector.ts) 的解锁回调。

## 矿石刷新与取矿

---

<br>

### 整批刷新与变异抽取

- [ ] **验收完成**

---

> 变异相对权重 = 衰减系数 ^（变异 ID − 首个变异 ID）<br>
> 变异概率 = 该变异相对权重 ÷ 全部变异相对权重之和

- 新 State 用负计时表示尚未初始化；首次构建 Game 时通过初始化 Action 立即生成矿石，并使取矿冷却就绪。不会等待一个刷新周期才产生首批。
- 每个在线 State Tick 在金币结算、取矿冷却推进之后增加刷新计时，达到当前间隔即整批生成并将刷新计时归零。旧批次剩余矿石全部替换，不累加，也不按超出的秒数补刷多批。
- 每次上线回调还会通过刷新 Action 立即换一批矿石；这个刷新不额外重置取矿冷却。未启用日程时不产生上线回调。
- 每批重新按顺序分配矿石 ID，每块独立调用框架 RNG 抽取一个互斥变异结果。离线与日程空闲不推进刷新计时。
- 调整数量、分布不会重抽现有矿石，下次刷新读取当前配置；缩短间隔后，在后续 Tick 达到条件时刷新。Game 分类汇总按变异 ID 排序展示。

**配置来源**

刷新触发：`config: 矿石整批刷新间隔（秒）`。<br>
批次数量：`config: 每批矿石数量`。<br>
变异分布：`config: 矿石变异概率曲线`；使用几何衰减分布，奖品数决定合法变异 ID，衰减系数决定归一化权重；奖品从首个正整数 ID 开始，不由展示采样范围决定。

实现来源：[State.ts](../Code/State.ts) 的 `advanceOneSecond()`、`refreshMiningOres()`；[Actions.ts](../Code/Actions.ts) 的 `InitializeMiningOresAction`、`RefreshMiningOresAction`；[Game.ts](../Code/Game.ts) 的 `BuildEditorUI()`、`onSessionStart()`、`UpdateUI()`。

### 取矿冷却与原料幸运

- [ ] **验收完成**

---

> 推进后冷却计时 = 较小值（原计时 + 一个在线秒，当前取矿冷却间隔）<br>
> 原料幸运 = 变异对应幸运曲线采样值 +（当前熔炼幸运等级 − 初始熔炼幸运等级）

- 置换或获取武器时，从剩余矿石中选变异 ID 最大者；相同变异选矿石 ID 最小者。每次完成一整轮锻造只消耗一块矿石，继承其变异，不再次随机原料幸运。
- 冷却计时达到当前间隔、存在矿石、变异 ID 在幸运曲线范围内、原料幸运和人物幸运均为正整数，才可开始。
- Action 执行成功后，无论达标、破损或消失，都会移除选中矿石并将冷却归零；被阻止时不消耗矿石、不重置冷却，也不进入随机锻造。
- 冷却最多储存一次机会，离线不推进。没有矿石时仍可在线蓄满冷却，但不会因冷却结束自行打造，除非已有置换队列请求。

**配置来源**

取矿间隔：`config: 打造取矿冷却（秒）`。<br>
基础原料幸运：`config: 矿石变异对应原料幸运`；直接传入选中矿石变异 ID，使用幂函数的基础值、倍率、幂值，不对结果取整。<br>
熔炼加值：代码固定的逐级等差加值，来自 `calculatePlayerUpgradeEffect()`；初始等级与每级增量取代码固定规则，不来自价格曲线。

实现来源：[Actions.ts](../Code/Actions.ts) 的 `ForgeSwordAction.getBestOre()`、`GetBlocker()`、`Apply()`；[Formulas.ts](../Code/Formulas.ts) 的 `calculatePlayerUpgradeEffect()`；[State.ts](../Code/State.ts) 的 `advanceOneSecond()`。

## 锻造与槽位置换

---

<br>

### 单锤概率与出炉结果

- [ ] **验收完成**

---

> 品质偏移 = 当前品质 − 本次人物幸运<br>
> 幸运差 = 将（原料幸运 − 人物幸运）限制在代码规定的对称差值上下限内<br>
> 好料成功概率 = 较小值（基础成功概率 ×（中性系数 + 好料修正系数 × 幸运差），概率总量 − 不变概率 − 消失概率）<br>
> 坏料或等幸运成功概率 = 基础成功概率 ×（中性系数 + 坏料修正系数 × 幸运差）<br>
> 破损概率 = 概率总量 − 成功概率 − 不变概率 − 消失概率

- 品质从本次人物幸运减去代码固定的起始品质偏移开始，不把负品质截断。当前品质偏移为负时不应用原料幸运修正；非负时才用上式调整成功率，不变与消失概率不变。
- 基础成功、不变、消失按当前品质偏移查代码固定数组；破损取剩余概率。各概率为百分数，每锤用框架随机数乘概率总量，依次划分成功、不变、破损、消失区间。
- 成功增加一个品质档；不变继续敲击，无锤数上限或保底；破损保留当前品质提前出炉；消失不产生成品。
- 达到人物幸运加目标偏移后停止。目标偏移取当前全局置换目标，不是每个槽位各自保存。
- 整轮在一个 Action 内完成，不模拟移动、熔炼或每锤时间，也不额外收取金币。成品使用代码固定初始等级，记录变异、原料幸运、本次人物幸运及结束品质；ID 为现存成品最大 ID 的后继值。
- 最近打造记录保存消耗矿石、幸运、结束品质、锤数、结果及成品和落槽 ID；消失时当前展示武器 ID 清空。

实现来源：[Formulas.ts](../Code/Formulas.ts) 的 `calculateForgeProbabilities()`：概率总量、基础数组、幸运差上限、好坏料系数及修正起点均为代码固定值；[Actions.ts](../Code/Actions.ts) 的 `ForgeSwordAction.Apply()`：起始偏移、品质步长及成品初始等级均为代码固定值。

**当前备注**

概率函数只接受规定品质偏移区间及正整数幸运；目标按钮覆盖代码允许的冲档范围。本文不展开概率数值表，具体固定参数须在上述函数核对；尚无本轮概率运行验证或平衡性验收。

### 目标选择与一次性置换队列

- [ ] **验收完成**

---

- 已解锁槽位的 Inspector 可在最低正偏移到最高正偏移目标之间切换；按钮显示从 +1 到 +4，对应连续整数档。目标全局生效，重复选当前目标或非法档位被拒绝。

- 不自动解锁槽位、不出售旧剑，也不为队列置换自动购买武器等级。Inspector 展示排队位置及当前执行阻碍。

### 武器等级与一键升级

- [ ] **验收完成**

---

> 单级费用 = 向下取整（费用基础值 + 当前武器等级 ^ 费用幂值 × 费用倍率）<br>
> 批量总费用 = 从当前等级起，逐档单级费用之和<br>
> 升级后等级 = 当前等级 + 连续可购买档数

- 只能升级已放入已解锁槽位且实际存在的武器；等级必须为合法整数，目标下一等级不得超过实际输入上限。当前配置只有限制下限，没有武器等级上限。
- 批量升级逐级累计，下一档累计费用超过当前金钱或下一等级超过配置上限时停止；余额恰好足够仍可购买。计划计算不改状态，成功 Action 一次扣总费用并增加对应档数。
- 选中槽位后 W，或 Inspector 的一键按钮，按槽位状态分支：锁定只解锁；已解锁空槽立即尝试取矿锻造并落槽，成功后再尝试将新武器升至当前余额可负担等级；已有武器则直接批量升级。
- 空槽获取若被阻止就不进入升级；锻造消失仍消耗矿石和冷却，但无武器可升级。获取与升级是两个独立 Action，不保证都成功。
- 升级只改该成品等级，不改品质、变异或幸运；新的等级倍率用于后续收益。Inspector 展示当前可升档数和总费用。

**配置来源**

升级价格：`config: 武器升级曲线.升一级费用`；用当前等级而非目标等级采样，逐档增加输入并向下取整。<br>
等级范围：`config: 武器升级曲线 → 输入下限与输入上限`；当前没有上限，展示采样上限不能当作满级。<br>
收益效果：`config: 武器升级曲线.等级倍率`；以升级后等级直接采样幂函数，不取整；详见[在线金币收益](#在线金币收益)。

实现来源：[Formulas.ts](../Code/Formulas.ts) 的 `calculateSwordUpgradePrice()`、`calculateSwordUpgradePlan()`；[Actions.ts](../Code/Actions.ts) 的 `UpgradeSwordAction`、`UpgradeSwordMaxAction`；[Game.ts](../Code/Game.ts) 的 `createSlotUpgradeAction()`、`upgradeSlot()`；[Inspector.ts](../Code/Inspector.ts) 的升级回调。

## 玩家升级

---

<br>

### 升级购买与幸运效果

- [ ] **验收完成**

---

> 当前级升一级费用 = 向下取整（费用基础值 + 当前等级 ^ 费用幂值 × 费用倍率）<br>
> 熔炼额外幸运 = 熔炼当前等级 − 熔炼初始等级<br>
> 锻造升级后人物幸运 = 升级前人物幸运 +（新等级锻造加值 − 旧等级锻造加值）

- Game 顶部提供熔炼幸运、武器锻造、收益倍率三个独立升级按钮，每次购买当前项的一个等级，各自消耗金币并保存等级。
- 先检查升级项有效、当前等级是曲线范围内整数、下一等级不超过上限、金钱足够，成功后才扣当前级费用并增加等级。余额不足或非法项不改变状态。
- 三类升级的初始等级、初始人物幸运及幸运每级步长均为代码固定值。熔炼加值参与后续原料幸运计算；锻造升级将等级效果差加到已有人物幸运，不重算覆盖人物幸运状态。
- 收益升级不修改人物幸运，只在以后金币结算时读取对应等级倍率；不改变已造武器的品质、等级或打造时幸运记录。
- 当前三个升级曲线均未设输入上限，预览窗口不构成满级；若配置上限，满级时停止购买与下一档预览。

**配置来源**

熔炼价格：`config: 熔炼幸运升级价格（临时数值）.升一级费用`；以当前熔炼等级采样。<br>

## 基地金币收益与日程

---

<br>

### 在线金币收益

- [ ] **验收完成**

---

> 单剑秒收益 = 品质基础秒收益 × 武器等级倍率 × 变异收益倍率 × 玩家收益倍率<br>
> 基地秒收益 = 全部有效槽位单剑秒收益之和 × 当前付费金币倍率<br>
> 每个在线秒的金钱 = 原金钱 + 基地秒收益

- 只有已解锁且引用实际存在武器的槽位产出；锁定、空槽、悬空引用跳过，未入槽库存武器不产出。
- 品质、成品等级、变异均使用武器当前字段，玩家倍率取当前已购收益等级，付费倍率取当前档位；人物幸运与原料幸运不额外直接乘入金币。
- 各曲线采样后相乘、汇总，最后乘付费倍率，直接累加金钱，不对秒收益或余额另行取整。界面金钱保留小数位只是显示，不截断 State 余额。
- 每个 State Tick 先结算本秒金币，再推进冷却和矿石刷新；随后 Game Tick 才自动购买倍率、执行置换。因此该 Tick 后半段新买倍率或新落槽武器不追补本秒收益。

**配置来源**

品质基础：`config: 武器品质基础秒收益（临时数值）`；以实际品质为整数输入，采样“基础值 + 指数底数 ^ 品质 × 倍率”，不取整；允许输入下限内的负品质，未设上限。<br>
等级倍率：`config: 武器升级曲线.等级倍率`；以当前成品等级采样“基础值 + 等级 ^ 幂值 × 倍率”，不取整。<br>
变异倍率：`config: 武器变异收益倍率（暂为1）`；以继承的变异 ID 直接采样幂函数，不取整。<br>
玩家倍率：`config: 玩家收益倍率升级（临时数值）.玩家收益倍率`；以当前收益等级直接采样幂函数，不取整。<br>
付费倍率：`config: 付费倍率逐档购买（钻石方案暂定数值）.最终金币倍率`；以当前已购档位直接采样指数函数，不取整、不连乘历史档位。

实现来源：[Formulas.ts](../Code/Formulas.ts) 的 `calculateBaseIncome()`、`calculateSwordLevelMultiplier()`、`calculatePaidMultiplier()`；[State.ts](../Code/State.ts) 的 `advanceOneSecond()`；[Game.ts](../Code/Game.ts) 的 `advanceOneSecond()`。

### 上线与离线收益结算

- [ ] **验收完成**

---

> 离线金币 = 上线结算时的基地秒收益 × 框架传入的离线秒数

- 当前配置已开启框架日程，按每天上线次数、每次在线时长和每次离线时长调度。Tick 只累计在线秒数，离线与当天剩余空闲不推进冷却、刷新或置换队列。
- 每次上线在首个 State Tick 前依次执行：刷新矿石、有效离线金币结算、当日钻石赠送、自动购买倍率。离线收益因此使用本次自动购买之前的倍率。
- 首次上线的离线参数为零，不创建有效领取；后续上线使用上一轮配置的离线时长，跨日不追加空闲秒数，也不使用真实系统时间差或在线 Tick 差。
- 离线参数必须是正整数，合法时用与[在线金币收益](#在线金币收益)相同的当前槽位、武器、玩家与付费倍率计算；不模拟离线逐秒成长，不额外打折、取整或限制领取时长上限。
- 领取 Action 本身没有离线批次去重或已领时长字段；正常入口由框架上线回调触发，回放使用记录中的离线时长。

**配置来源**

日程：框架保留配置 `__framework.schedule`，中文名未配置，保留实际键；使用启用状态、每天上线次数、在线秒数和离线秒数。不是普通玩法配置，不使用虚构的 `config:` 中文名。<br>
收益采样：见[在线金币收益](#在线金币收益)，全部按上线结算时状态和配置计算。

实现来源：[Game.ts](../Code/Game.ts) 的 `onSessionStart()`；[Actions.ts](../Code/Actions.ts) 的 `ClaimOfflineIncomeAction`；[Formulas.ts](../Code/Formulas.ts) 的 `calculateBaseIncome()`。框架回调与 Tick 顺序依据本轮读取的 `ScheduleApi.md`、`GameApi.md`，非项目自行实现日程引擎。

## 钻石与付费金币倍率

---

<br>

### 初始资源与每日赠送

- [ ] **验收完成**

---

> 赠送后钻石 = 赠送前钻石 + 当前每日赠送钻石

- 新 State 直接读取初始钻石和默认已购倍率档位；没有实际执行“先发新手钻石再扣款购买默认档位”的交易。配置名中的新手说明不等于发生过赠送或扣款。
- 构建 Game 时按当前日程日赠送；没有日程上下文时使用代码默认首日。每次上线也尝试赠送，同日已有记录则跳过。
- 奖励日须为正整数且严格晚于最近已领奖励日；成功只发一次当前每日额度并将最近日改为传入日，不按跳过的日数补发。
- 钻石赠送不受玩家收益倍率、武器收益或付费金币倍率影响。日程关闭时无自动跨日来源，持续在线 Tick 不会凭真实日期另发每日奖励。

**配置来源**

初始余额：`config: 初始钻石（新手35钻已用于默认2倍）`；新 State 和快照缺省恢复时直接读取。<br>
初始档位：`config: 新手默认已购倍率档位`；新 State 和快照缺省恢复时直接赋值，不扣钻石。<br>
每次奖励：`config: 每日赠送钻石`；成功领奖时读取当前配置。<br>
首日及未领奖标记：代码固定值，来自 `BuildEditorUI()` 和 `State.lastDiamondRewardDay`。

实现来源：[Main.ts](../Code/Main.ts) 的 State 构造；[State.ts](../Code/State.ts) 的钻石初始化；[Actions.ts](../Code/Actions.ts) 的 `ClaimDailyDiamondsAction`；[Game.ts](../Code/Game.ts) 的 `grantDailyDiamonds()`、`BuildEditorUI()`、`onSessionStart()`。

### 逐档购买与倍率作用

- [ ] **验收完成**

---

> 下一档 = 当前档位的紧邻后继档<br>
> 本档钻石价格 = 价格基础值 + 目标档位 ^ 价格幂值 × 该档价格倍率<br>
> 购买后钻石 = 当前钻石 − 下一档本档钻石价格<br>
> 生效金币倍率 = 下一档最终金币倍率

- Game 购买按钮仅购买下一档；当前档位须为配置范围内整数，达到上限后停止，不采样范围外的下一档。
- 钻石至少等于下一档价格才可购买；成功扣价格并提升一档，恰好足够可购买；余额不足、非法档位或满档时状态不变。
- 新档最终倍率替换旧倍率，不将历次倍率连乘；只作用于在线与离线金币，不影响钻石、幸运、概率、矿石数量或价格。
- Game 显示当前倍率、余额、当前档、下一档价格与阻碍，以及从曲线起始档到当前档的倍率序列。该序列由当前档位推导，不是逐笔交易记录。

**配置来源**

最终倍率：`config: 付费倍率逐档购买（钻石方案暂定数值）.最终金币倍率`；以当前或紧邻下一档为输入，采样“基础值 + 指数底数 ^ 档位 × 倍率”，不取整。<br>
购买价格：`config: 付费倍率逐档购买（钻石方案暂定数值）.本档钻石价格`；以目标下一档为输入，按各档单点线性参数取价格，经该列幂函数计算，不取整；不使用当前档费用，不累加旧档成本。<br>
档位边界：`config: 付费倍率逐档购买（钻石方案暂定数值） → 输入下限与输入上限`；当前价格参数的分段覆盖合法档位，预览范围不替代输入范围。

实现来源：[Formulas.ts](../Code/Formulas.ts) 的 `calculatePaidMultiplier()`、`getNextPaidMultiplier()`；[Actions.ts](../Code/Actions.ts) 的 `BuyPaidMultiplierAction`；[Game.ts](../Code/Game.ts) 的购买按钮与 `UpdateUI()`。

### 自动购买开关

- [ ] **验收完成**

---

- 新 State 默认关闭自动购买。Game 开关通过 Action 保存启用状态，非布尔值或重复设置被拒绝。
- 切换开关后立即尝试购买；开启时还在构建 Game、上线赠送后及每个 Game Tick 尝试。
- 一次尝试可连续购买多个紧邻档，直至余额不足、满档或消费失败；不保留“只买一档”的限制。关闭后不再自动购买，但手动购买仍可用。
