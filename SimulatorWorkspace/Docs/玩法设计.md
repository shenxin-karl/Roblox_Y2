## 3. 系统规则

- State 记录当前金钱和各槽位是否解锁，初始金钱来自 Config 最外层，初始解锁数量来自“槽位配置”；默认前 5 个槽位（ID 1～5）已解锁，其余未解锁，初始解锁不扣钱。
- 选中槽位后在 Inspector 点击“解锁”，按当前曲线价格扣除金钱并解锁该槽位，不要求先解锁相邻槽位。
- 金钱不足、槽位不存在或已经解锁时不扣钱、不改变解锁状态；同一槽位不能重复购买。
- 矿石按累计在线时间刷新：初始矿石为空，每满 300 秒生成一批 20 个并整批替换旧矿石，不累加。每块矿石按当前概率曲线独立抽取一个变异结果，刷新前保持不变；离线不推进刷新计时。
- 不再自动取矿、打造或放置。点击 Game 的“打造”才取走剩余矿石中变异 ID 最大的 1 块，同档时取 ID 最小的矿石；保留 30 秒在线取矿冷却，无矿或冷却未结束时按钮禁用，冷却结束不会自动执行。
- 每块矿石转换为 1 份原料，继承矿石变异，幸运 W 取该变异对应的固定配置值，不重新随机变异或幸运。
- 一次“打造”从人物幸运 P 对应的品质 P−4 开始逐锤计算，成功提升 1 品质，不变继续敲击；到 P+1 主动停止，破损则保留当前品质提前出炉，消失则不产生武器。本次将取矿、制料和整轮打造作为一次操作，不额外模拟移动、熔炼或单锤耗时，不额外收费。
- Game 顶部显示本次打造的当前武器及品质、变异、等级。玩家点击槽位选中目标，再点击“放入”或“替换”；不自动比较品质，允许玩家主动选择替换，包括同品质或更低品质。被替换的旧剑直接丢弃并从 State 删除，不自动解锁槽位或出售武器。
- 成品初始等级为 1，与锻造品质分开。选中已经放有武器的已解锁槽位后，可点击升级按钮，花金币升 1 级；未入槽武器、空槽、锁定槽位不能升级，余额不足不扣款。升级只改变该成品等级，不改变品质或幸运。

## 4. 交互流程

Game 顶部展示当前武器、金钱、矿石数、取矿冷却及选中槽位详情，并提供“打造”“放入／替换”“升级”按钮。下方保留 30 个浅蓝色方形槽位，每行 6 个、共 5 行，不使用滚动容器或槽位区外框底色。按钮横纵间距统一为 12px，左上角显示槽位 ID；空槽显示“已解锁”，放入武器后显示品质和等级，选中槽位使用高亮边框。点击槽位仍同步 Inspector 选择，原有解锁入口保持不变。

## 6. 实现说明

金钱保存在 `State.money`，槽位列表保存在 `State.slots`，每项记录 `id`、`unlocked` 和 `swordId`（空槽为 `null`），随状态快照保存与恢复。Game 的槽位按钮只切换编辑器选择，Inspector 的解锁按钮消费 `UnlockSlotAction` 完成扣款与解锁；价格由共用公式按当前 Config 采样，操作支持 Action 序列化回放。

当前矿石保存在 `State.miningOres`，每项记录本批次内的 `id` 和变异结果 `mutationId`；刷新已过秒数保存在 `State.miningRefreshElapsedSeconds`。由 `State.advanceOneSecond()` 推进计时并按当前 Config 自动整批刷新，使用框架 RNG，随状态与 RNG 快照保存和恢复，恢复时不重新抽取。

`State.oreCollectElapsedSeconds` 保存取矿冷却计时，`State.playerLuck` 保存人物幸运，`State.swords` 保存当前拥有的全部成品（含已入槽武器与等级），`State.currentSwordId` 保存当前展示武器，`State.lastForgeResult` 保存最近一次消耗的矿石、原料幸运、结束品质、锤数、出炉结果及放置位置。手动操作分别消费 `ForgeSwordAction`、`PlaceSwordAction` 和 `UpgradeSwordAction`，支持快照恢复与 Action 回放；UI 刷新只读状态，选中槽位属于 Game 的临时 UI 选择。旧 `autoForgeSword` 类型仅保留原语义用于历史回放，不再由在线 Tick 自动触发。当前不新增矿石或完整背包 UI，不实现收益结算和出售。
